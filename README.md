### ◈ Executive Overview

Modern large language model inference typically requires high-end accelerator hardware or massive DRAM capacities. When RAM is constrained, traditional runtime architectures rely on operating system memory mapping (`mmap`). Under strict memory limits, `mmap` suffers from catastrophic page thrashing and OS kernel OOM-killer termination (`SIGKILL`).

**Kura replaces virtual memory paging with a storage-native, decoupled memory architecture.**

By treating CPU SIMD execution units, host RAM buffers, and NVMe block devices as a single coordinated substrate, Kura achieves high-throughput local inference directly on commodity developer machines.

### ◈ Core Architectural Tenets

1. **Decoupled Memory Execution:** Model weights reside on NVMe storage and are streamed into small, reusable staging buffers asynchronously. RAM holds only activation vectors, embedding tables, and active Paged KV caches.
2. **Physical Layout Coalescing (LOOM):** Reorganizes model weights into strictly contiguous forward-pass order. Eliminates random head seeks, converting random I/O into saturating sequential DMA transfers.
3. **Adaptive Lookahead Prefetching:** The autonomous SENSE profiler measures the host $T_{\text{io}} / T_{\text{compute}}$ ratio in real time, selecting lookahead windows ($W=1 \dots 3$) to completely hide NVMe read latency behind CPU SIMD computation.
4. **Chunked GEMM Speculative Verification:** Batches $K=4$ draft tokens into single matrix operations with shared weight dequantization, delivering $\ge 2.18\times$ verification speedup with 100% token sequence parity.
5. **Cross-Platform Bitwise Parity:** Hand-tuned AVX-512 FMA and ARM NEON kernels guarantee identical numerical outputs across x86-64 workstations and ARM64 Apple Silicon.
6. **Zero Telemetry:** Strict privacy-first design. No analytics, no phone-home callbacks, and 100% local offline execution.

### ◈ The MoE Architectural Superiority Law

When inference runs under decoupled memory constraints where weights must be read from storage, **Sparse Mixture-of-Experts architectures demonstrate an insurmountable physical throughput advantage over Dense architectures**:

<div align="center">
  <img src="benchmarks/svg/moe_vs_dense.svg" alt="MoE Superiority Law" width="100%"/>
</div>

$$\text{Throughput}_{\text{MoE}} \approx \frac{\text{Storage Bandwidth}}{\text{Active Weights per Token}}$$

Because OLMoE 1B-7B routes each token to only 8 of its 64 experts, it transfers only **68 MB** of weights per token (4.1% of total model weights), achieving **15.2 tok/s** on an entry-level $80 SSD. By contrast, Dense 70B must transfer all **35,000 MB** per token, requiring a 15-drive enterprise NVMe striping array to reach the same threshold.

### ◈ Quickstart & Installation

Kura provides an interactive, zero-telemetry terminal installer that probes your CPU vector ISA (AVX-512 / ARM NEON), measures local storage bandwidth, and configures the runtime environment:

```bash
# Clone the benchmarks and documentation repository
git clone https://github.com/fraol163/kura-benchmarks.git
cd kura-benchmarks

# Launch the interactive system probe and installer
node bin/install.js
```

#### CLI Introspection

```bash
# Probe hardware vector extensions and NUMA affinity
kura profile --json

# Inspect the LOOM memory layout plan for a target RAM budget
kura plan --model ./models/olmoe-1b-7b-q4_k_m.gguf --budget 4096

# Launch the OpenAI-compatible HTTP streaming server
kura serve --port 8080 --threads 8
```

#### OpenAI-Compatible Streaming

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "olmoe-1b-7b",
    "messages": [{"role": "user", "content": "Explain storage-native execution"}],
    "stream": true
  }'
```
